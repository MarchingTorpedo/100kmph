# @100kmph/storefront

The customer-facing site. Today: a preview of the landing page, scenes 1 and
2 of [`docs/motion-spec.md`](../../docs/motion-spec.md), built with Astro 7 on
`@100kmph/design`. The poster, copy and rider silhouette are placeholders.

## Run it

From the repo root:

```sh
pnpm install
pnpm --filter @100kmph/storefront dev        # http://localhost:4321, live reload
```

Production build and preview (what the numbers below were measured on):

```sh
pnpm --filter @100kmph/storefront build
pnpm --filter @100kmph/storefront preview    # http://localhost:4321
```

Checks:

```sh
pnpm --filter @100kmph/storefront typecheck      # astro-check
pnpm --filter @100kmph/storefront test           # budget-checker unit tests
pnpm --filter @100kmph/storefront check:budget   # after a build: initial JS <= 170 KB gzip, poster sizes
pnpm --filter @100kmph/storefront exec playwright install chromium   # once
pnpm --filter @100kmph/storefront test:e2e       # Pixel 7, iPhone 13, desktop; full/reduced/lite
```

## How the scenes work

| | Full motion | Reduced motion / footer toggle | Lite (Save-Data, 2g, <= 2 GB) |
|---|---|---|---|
| 1 Ignition | CSS only: needle and counter 0 to 100, light sweep, gauge dissolves into the headline (1.4 s) | Static gauge at 100, headline fades in | Same as full (CSS only, cheap) |
| 2 Crossing | Scroll-scrubbed over 1.5 viewports, pinned (CSS sticky) for the middle 40%; numeral stretches to wdth 125 mid-way | Rider parked mid-frame, no pinning | One 600 ms slide on enter, no pinning |
| Velocity Width | On the h1 and h2 | Off (wdth 100) | Off |

- Scroll scrub uses CSS scroll-driven animations where supported. Elsewhere,
  `src/scripts/crossing-gsap.ts` (GSAP + ScrollTrigger, 43 KB gzip) is loaded
  after `load`. `?scrub=gsap` forces that path for testing.
- `src/scripts/landing.ts` is the only initial script (about 3 KB gzip). The
  inline head script from `@100kmph/design/boot` sets `data-motion` and
  `data-lite` before first paint.
- `styles/crossing.css` writes the scroll animations as longhands on purpose:
  the CSS minifier folds `animation` + `animation-timeline` into an invalid
  shorthand.

## Things to look at in the browser

1. Load the page: needle sweeps, yellow light passes, headline settles.
2. Scroll slowly through the crossing: rider crosses, the ghost 100 widens as
   the rider passes the middle, the stage holds still for a while.
3. Fling the scroll: both headlines stretch (down) or compress (up) and settle
   back to normal width when you stop.
4. Footer "Reduce motion": everything goes static at once, the button stays
   where it is, and the choice survives a reload.
5. DevTools > Rendering > "Emulate CSS prefers-reduced-motion": static frames.
6. DevTools > Network > "Slow 3G" plus Save-Data (or run with a 2 GB
   `deviceMemory` override): lite mode.

## Placeholders

`src/assets/poster-placeholder.jpg` is generated by
`scripts/make-placeholder-poster.mjs` (`pnpm poster:placeholder`). Replace it
with the client poster when it arrives, keeping a file name that starts with
`poster` (the budget check looks for it and fails if there is none). The real
poster also needs a portrait crop for phones; the 16:9 image is upscaled about
3x on a portrait phone screen.
